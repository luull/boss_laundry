# Migrasi BOZZ Laundry: MySQL → Supabase PostgreSQL

Panduan ini menjelaskan cara mengatur, menjalankan migrasi, build, dan
menjalankan aplikasi setelah database dipindahkan dari MySQL ke Supabase
PostgreSQL. Aplikasi tetap Java Swing + Maven (tidak diubah ke web/framework
lain).

---

## 1. Ringkasan Perubahan

| Area | Sebelum | Sesudah |
|------|---------|---------|
| Database | MySQL/MariaDB lokal | Supabase PostgreSQL (Session Pooler) |
| Driver JDBC | `com.mysql:mysql-connector-j` | `org.postgresql:postgresql` 42.7.14 |
| Kredensial | hardcode di `Koneksi.java` (`root`, tanpa password) | file `.env` / env var, **tidak** di source code |
| Koneksi gagal | `return null` diam-diam → `NullPointerException` | lempar `KoneksiException` dengan pesan jelas |
| Pencarian (`LIKE`) | case-insensitive (default MySQL) | `ILIKE` (menjaga perilaku sama di PostgreSQL) |
| Load report (Laporan) | `getResource().getPath()` (gagal di dalam JAR) | `getResourceAsStream()` (aman dari JAR) |
| Logo struk | `logo.png` relatif folder kerja | diambil dari classpath `/image/logo.png` + fallback |

---

## 2. Menjalankan Migrasi SQL di Supabase

1. Buka dashboard Supabase → **SQL Editor** → **New query**.
2. Salin seluruh isi file [`supabase_migration.sql`](./supabase_migration.sql).
3. Klik **Run**. Tunggu sampai muncul *Success*.
4. Verifikasi di **Table Editor** (schema `public`) — harus ada 5 tabel:
   `master_cabang`, `master_layanan`, `master_pelanggan`, `master_user`,
   `transaksi_laundry`, lengkap dengan data awalnya.

> ⚠️ Script membuat ulang tabel (ada `DROP TABLE IF EXISTS ... CASCADE`).
> Jalankan hanya pada database setup awal, **bukan** database produksi berisi
> data penting. File `bozz_laundry.sql` asli tidak diubah.

Perubahan skema utama: `AUTO_INCREMENT` → `GENERATED BY DEFAULT AS IDENTITY`,
`int(11)` → `integer`, `double` → `double precision`, `decimal(10,2)` →
`numeric(10,2)`, `enum(...)` → `varchar + CHECK`. Sequence IDENTITY
disinkronkan dengan `setval` agar INSERT berikutnya tidak bentrok primary key.

## 3. Mengatur Koneksi Supabase (lokal, tanpa commit kredensial)

Aplikasi membaca konfigurasi dengan prioritas:
**environment variable → file `.env` → file `db.properties`**
(dicari di: path `-Dbozz.db.config=...`, lalu folder kerja, lalu
`~/.bozzlaundry/`, lalu classpath).

### Opsi A — file `.env` (yang sedang Anda pakai)

Buat file `.env` di root proyek:

```
url="jdbc:postgresql://aws-0-<region>.pooler.supabase.com:5432/postgres?user=postgres.<ref>&password=<PASSWORD>"
host="aws-0-<region>.pooler.supabase.com"
port="5432"
database="postgres"
user="postgres.<ref>"
```

Loader otomatis membaca `url` (yang sudah memuat user & password), menambahkan
`sslmode=require` bila belum ada, lalu connect.

### Opsi B — `db.properties`

Lihat contoh di [`db.properties.example`](./db.properties.example). Salin
menjadi `db.properties` lalu isi `db.host`, `db.user`, `db.password`, dst.

### Opsi C — environment variable

```
export SUPABASE_DB_HOST=aws-0-<region>.pooler.supabase.com
export SUPABASE_DB_PORT=5432
export SUPABASE_DB_NAME=postgres
export SUPABASE_DB_USER=postgres.<ref>
export SUPABASE_DB_PASSWORD=<PASSWORD>
export SUPABASE_DB_SSLMODE=require
```

> `.env` dan `db.properties` sudah masuk `.gitignore` — jangan pernah
> di-commit. Jika password mengandung karakter spesial (`@ : / ? # & %`),
> lakukan percent-encoding saat ditaruh di dalam `url`.

## 4. Build (Maven)

Butuh JDK 17+ (proyek target Java 17; teruji dengan Maven 3.10 + JDK 27).

```bash
cd /path/ke/BozzLaundry
mvn clean package
```

Hasil: `target/BozzLaundry-1.0-SNAPSHOT.jar` (shaded/uber-JAR, ±23 MB) yang
sudah memuat driver PostgreSQL, JasperReports, iText, dan semua resource
(report `.jrxml`/`.jasper` + gambar).

---

## 5. Menjalankan Aplikasi

Dari folder yang berisi `.env`:

```bash
java -jar target/BozzLaundry-1.0-SNAPSHOT.jar
```

atau dari Kiro/terminal dengan path config eksplisit:

```bash
java -Dbozz.db.config=/path/ke/.env -jar target/BozzLaundry-1.0-SNAPSHOT.jar
```

Login awal (dari data seed): `admin` / `admin123`.

## 6. Catatan Keamanan (penting untuk multi-cabang)

- **Akses JDBC langsung dari desktop membawa kredensial database.** Siapa pun
  yang punya akses ke komputer / file JAR + `.env` berpotensi membaca
  kredensial dan mengakses seluruh database. Environment variable maupun file
  lokal **tidak** benar-benar menyembunyikan kredensial dari pengguna di mesin
  itu.
- **RLS tidak melindungi koneksi ini.** Koneksi memakai kredensial database
  (role `postgres.<ref>`) yang mem-bypass Row Level Security. RLS hanya efektif
  untuk akses lewat Supabase API (anon/service key), bukan JDBC langsung.
  Karena itu RLS sengaja tidak diubah pada migrasi ini.
- **Jangan menaruh service role key** di aplikasi desktop.
- **Password tersimpan plain text** di tabel `master_user` (bawaan aplikasi
  lama). Direkomendasikan hashing (mis. BCrypt) — lihat bagian Rekomendasi.
- **Rekomendasi untuk distribusi banyak cabang:** sisipkan lapisan
  **backend/API** (mis. Supabase Edge Functions / REST API sendiri) sebagai
  perantara. Desktop memanggil API dengan token per-user; kredensial database
  hanya ada di server. Dengan pola ini RLS/otorisasi baru benar-benar efektif.

---

## 7. Rekomendasi Lanjutan (opsional)

1. **Hash password** `master_user` dengan BCrypt dan ubah query login agar
   memverifikasi hash (bukan membandingkan plain text).
2. **Backend/API** untuk arsitektur multi-cabang (lihat di atas).
3. **Rotasi password database** secara berkala dari dashboard Supabase.
4. Pisahkan role database read/write bila nanti pakai backend.
